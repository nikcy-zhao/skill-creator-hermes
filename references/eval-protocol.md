# 评测编排细则

## 派发提示词固定条款（每个执行器子代理都必须写入）

- 「单轮执行，完成后直接交付，不再派生自己的对照/评测子代理；交付即终止，禁止交付后继续观察、替其他 run 代工或派生任何代理」（防递归）
- 「写入 <run>/outputs/ 完整路径」——汇总脚本从委派账目取回token真值的匹配锚点，缺了它token数掉到估算级；评测子代理会真执行任务，产物只许落 <run>/outputs/（或 /tmp 演练路径），禁止写入 `~/Documents/skills/` 与 `~/.hermes/skills/`——真实任务也会被它当真做完，写进真目录就长出野生技能残留
- 基线子代理一律不装载被测技能——无技能是基线语义的一部分，装载了就不是基线了
- 基线的「不读技能」约束必须覆盖技能的**所有副本**（夹具、源库、`~/.hermes/skills/` 部署副本），只禁夹具会被「读源库」绕过
- 装载方式与 `aggregate --verify` 的匹配：verify 的「技能真用」检查认 skill_view 调用记录；执行器若以「直接读 SKILL.md 文件路径」方式装载（多技能批量评测的常用形态），verify 必然整批误报「技能未真用」——此类装载跳过 --verify，技能真用以子代理转录（装载动作自述＋行为分化）佐证
- token 真值链路的版本现实：新版 delegation 批次（deleg_* 形态）不落 state.db 的 async_delegations 表（该表只收旧版单任务），锚点齐全也取不回真值——此时唯一出路是 `--allow-estimate` 并在报告如实标注降级原因（真值链路断，非估算凑数）；核心 Δ 指标不受影响（来自 grading.json 真值）

## 污染防护（夹具与产物的两条红线）

- 夹具只放待处理对象，禁止夹带被测技能自己的规则文本/标准答案——基线组读到它，污染就发生了
- 写任何文件前先确认目标路径属于本 run 的目录树（相对本 run outputs/ 的路径才写），盘上已存在同名文件时先查其归属再决定覆盖或改名——多代理并行时同名路径不唯一，write 前只看路径不看会话归属曾覆盖兄弟 run 产物

## 基线复用

基线恒为无技能运行，与技能版本无关——技能改动不影响基线，故复用只看提示词。提示词自上一次迭代未变时，基线不重跑：汇总时加 `--reuse-baseline <上一次迭代目录>`，脚本自动把上一次 without_skill 各 run 的 grading.json/timing.json 复制进本轮空 run（缺文件即报错退出，不静默漏带）；本轮已重跑的 run 不覆盖。提示词变了才须重跑基线。

## 判据起草

- 每条判据先过区分度自查：**裸模型凭通用能力能过吗？能过就没区分度**——改写成考技能私有内容（引用规范的具体条目、用了技能的脚本/工具/流程步骤），改不成就删
- 区分度自查必须考虑**基线探索自学**路径：裸模型可在本机探索后自学（翻源码、看部署库、自研同名脚本）——判据关键词若会被自学产物命中（如工具名出现在基线自研代码里），该判据实际无区分度；能考"直接引用现成私有资产 vs 从零自研"的，以效率/成本差呈现而非仅 pass 率
- 用例同理：任务里技能没提供模型本来不知道的东西（私有规范/工具/流程），不进对照评测，只会稀释 Δ
- 主观型技能不加强加的判据，靠定性评估

## 判据脚本化

- 逐条判据二选一：能机械验证的（存在性→正则/关键词、格式→模式匹配、数量→计数比对）当场写进该 eval 目录 `check.py`（接 run 的 outputs 目录为参数，stdout 输出完整脚本判 grading.json——expectations＋summary 段；通用判据从 `scripts/check_common.py` import）；需语义理解的标「模型判」留给评分子代理
- 判据不变则 check.py 跨迭代复用；首次使用前标定——同一 run 脚本判与评分子代理双跑对齐，一致性 ≥90% 方可信；定稿全量评测仍用模型判复核
- 写 check.py 前先查 `scripts/check_common.py` 的实际导出（`grep '^def '`），接口名以盘上为准、禁止凭印象写 import——自测能抓住运行时错，但查证一步免返工一轮
- `text_matches` 接 pathlib.Path（不收 str）；其 findall 无 `re.M`——正则用行锚（`^`）须自带 `(?m)`，否则只匹配文档首行
- check.py 自测须覆盖判定主路径：造最小真产物（如一行假的 SKILL.md）让每条判据真实执行一次，只跑空 outputs 验证"不崩"不算自测——空目录走 else 分支，判定代码根本没执行，真实产物一来才在第一次执行时崩溃
- check.py 用 glob 时必须带 `recursive=True`——缺了它 `**` 只是死字符不跨目录（实测多判据整批误判 FAIL）；且 `**` 默认**不进点开头隐藏目录**（如 `.gzh-article/`），隐藏层路径要显式写全或换 os.walk
- `file_contains`＋not_contains 型判据须显式定义「文件缺失」语义：防泄漏类（不含密钥/不含完成态）缺文件应判过（无文件即无泄漏）；要求在场类缺文件判挂——不写死就跑出反直觉结果
- 起草判据前先通读被测技能的**拍板点**：技能规范常规定某些节点「等用户确认后落盘/不越界代写」——正常例若把「产物已落盘」当断言，会把技能的正确停点行为判 FAIL（实测多篇横评类用例整批判反）；停点类正确行为的断言应锚定「回复中出现待拍板问题」而非产物存在性
- check.py 的判据根目录基准要在首用前实测核对（如产物实际在 `<run>/outputs/workspace/` 而判据以 `<run>/outputs/` 为根，全部 file 判据静默空转）——抽一个真实 run 试跑 check.py 再定稿判据表

## 评分子代理

- 读 `templates/grader.md`，逐判据评估，存 `<run>/grading.json`
- 评分子代理常误写到配置目录，发现错位挪回
- 脚本判与模型判混合时两段 expectations 合并落盘

## 分层升级

迭代期（4↔5 循环）的方向判断机制，定稿验证不适用：

- 每轮改动后：1 层冒烟（1 个区分度最高用例 × 1 run × 关键判据，约全量 1/6 开销）——Δ ≥ +15% 保留、Δ ≤ −15% 回滚，均不加测
- 模糊带（−15%~+15%）补到 3 run 抵消随机波动，仍模糊则全量确认跑
- 收敛出口的最后一轮**必须全量**——定稿数据永远足样本，冒烟数据不进报告

## 结果分析

- 结论**按用例分列组间差**，混合均值 Δ 只是参考且用例数 ≥3 才有意义
- 汇报每个用例各配置的 run 数，n=1 与 n=3 可信度不同

## 盲比较

要严格比较两个技能版本（用户问「新版本真的更好吗？」）时用：

- 新旧版本各自跑同一任务：同一用例、同一提示词、同一模型；旧版跑前确认「4. 改进技能」Step 1 的快照已在
- 两份输出连同各自的token消耗匿名交独立代理盲评：token 取本次 `benchmark.json` 的真值列（`tokens_source`＝state.db-delegation 级）；仅非 delegate 的单跑场景才读 usage.json/timing.json。子代理读 `templates/comparator.md`，按量规打分并把token效率计入最终分
- 揭盲分析：评完后派分析子代理读 `templates/analyzer.md`，对照两版技能与执行记录产出胜者强项/败者弱项/改进建议

## 触发评测查询

- 查询必须真实——具体路径、口语化、可带错别字、有分量（一步小任务永不触发）
- 负例要"差一点就中"，明显无关的负例什么都测不出
- 优化循环按训练集/留出集切分选 `best_description`（留出集＝不参与训练、只用于最终验证的查询子集）：只在没见过的查询上分高才算真优化，防止只背熟训练查询

## 查看器备注

- 迭代 2+ 加 `--previous-workspace <workspace>/iteration-<N-1>`；跑过 description 优化再加 `--trigger-report <run_loop结果.json>`
- 服务器版页面带心跳（每 5s /ping）：页面开着服务器在，页面关闭后约 30s（`--idle-timeout` 可调，0 禁用）无心跳即自动退出释放——流程中断不再泄漏进程，读完反馈后无需手动 kill
- 起查看器必须 background=true 且当轮即回（告知用户地址＋"关闭页面即自动释放"）；禁止在会话内用长 sleep/轮询等页面事件——会阻塞会话；确需用户配合时发提示说明操作（如"看完直接关页即可，无需其他动作"），验证查看器行为只用 idle-timeout≤5 的一次性短测
