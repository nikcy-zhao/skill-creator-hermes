# 废话形态清单

「写作规范」首条的落地判定是判定器，本清单是已判明形态的库存（开放清单，遇清单外形态判明后补录）。凡命中即删。

## 已判明形态

- 总括导语复述标题/正文/description 已有内容（description 换皮、How to Run 换皮是导语重灾区）；正文里与 description 重复的触发条件同理删
- 解释性铺垫
- 与对照表重复的条目
- references 分组说明
- markdown 链接语法：`[名字](path)` 简写为 ``path``
- 表格/清单里的"同上"
- 括号给理由
- 场景列举（"撰写/改进/自检时对照"）
- "直接抄走"式注解（模板天生就是抄的，不用教）
- 引用点旁的元说明：写给人的解释（"勿整篇读""该节 N token vs 整篇 M""按某某法抽取"）挂在引用点旁——给 agent 的引用只需"意图词 + 可照抄的命令块"，命令在场就没人绕道整篇读
- 无生产者的 schema/规范条目：引用文件里描述某数据结构，但全库无脚本生产或消费它——照写必误人
- 叙述代码已内建、必然发生的行为：脚本自动做的校验/重试/回退/取数不需要 agent 知道，写了也不改变任何动作（保留的只有 agent 须配合的编排契约）

## 红线

精简的终点是"执行者一眼看懂"，不是字数最少——把目录树压成一行路径链、把规则压成机器式缩写是压缩过头，人读不懂=失败。
