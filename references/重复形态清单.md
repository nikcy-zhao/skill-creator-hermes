# 重复来源排查清单

## 形态枚举

- **① skill 内部重复**：前面段落与后面段落对同一功能用相似/相同说法各写一遍——通读时逐行问：这话别处是否已经有了？纵向问前面出现过吗，横向问其他节/引用文件/Pitfalls 是否已标注，出现过的删后文、留首次或留权威处。
- **② 与引用文件重复**：references/templates 里已描述的内容，SKILL.md 正文又描述一遍——正文只留"何时读哪个文件"的指引与行为规则，查表性内容归引用文件，两处都有的删正文副本。
- **③ 与被装载技能重复**：正文要求装载另一技能完成某功能，本 skill 又把该功能描述一遍——判定法"源有删、源无留，留的注明源为何没有"，权威方保留原文，本 skill 只留增量并注明差距。
- **④ 跨副本重复**：源库与部署副本各持一份，改动只落一处导致内容漂移出两套表述——每次改动后两副本 `diff` 对齐。
- **⑤ 迁移残留**：规则搬到新位置后旧位置留下"空壳标题+指针"——迁移时删旧壳。
- **⑥ 模板/总结重复**：模板行内注释已逐字段标注，正文/总结段又复读一遍——模板成为唯一载体后，旁条收敛为指针或一句纪律。
- **⑦ 术语改名残留**：外迁/改写时把节名或术语改了名（如「写作规范」改「写作纪律」），流程里其他引用点还叫旧名——外迁内容一律沿用原节名，改名必须全文 grep 旧名清零。
- **⑧ 修法已内置化**：脚本升级后 Pitfalls 里旧修法成了脚本默认行为——改脚本后反向检查引用该行为的文档条目，滞后即改写或删。
- **⑨ 跨条目修法重复**：Pitfalls 内多条坑的修法相同——横向比对各条修法，共享修法的条目合并。

## 越界分流

两个自制技能整体功能重叠时，走 hermes-skill-curation 的合并判定。
